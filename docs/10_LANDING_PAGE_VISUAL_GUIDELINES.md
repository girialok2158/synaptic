Synaptic Landing Page Visual Guidelines

Version: 1.0
Status: Approved Design Foundation
Applies To: Public Marketing Website (Landing Page Only)

⸻

Purpose

This document defines the visual foundation for the Synaptic landing page.

Its purpose is to ensure that every section of the landing page feels like it belongs to one cohesive product experience.

These guidelines should be followed consistently during frontend implementation.

The objective is not pixel-perfect replication of another product, but consistent execution of Synaptic’s design language.

⸻

Design Philosophy

The landing page should communicate:

* Confidence
* Intelligence
* Professionalism
* Focus
* Simplicity
* Trust

The interface should feel:

* Spacious
* Calm
* Modern
* Product-first
* Editorial
* Premium

Marketing should never overpower usability.

The product itself is the hero.

⸻

Layout Philosophy

The page should read like a carefully designed narrative rather than a sequence of disconnected sections.

Every section should have a clear beginning, generous breathing room, and a defined visual purpose.

Avoid dense layouts.

Whitespace is an active design element.

The hero, workspace showcase, and final CTA should receive the largest spacing.

Supporting sections (social proof, FAQ) may be slightly more compact to maintain page rhythm.

Avoid arbitrary spacing adjustments.

Every section should feel intentionally aligned with the next.

Borders

Border Radius

Use one consistent radius family.

Suggested hierarchy:

* Small radius for chips, badges, and compact controls.
* Medium radius for inputs, buttons, and cards.
* Large radius for prominent surfaces such as feature groups, workspace frames, and modal previews.

Avoid mixing many different corner treatments across the page.

Motion never entertains.

⸻

Motion Easing

Movement should accelerate naturally and settle gently.

Avoid exaggerated bounce effects or elastic motion in the landing experience.

⸻

Scroll Behavior

Scrolling should feel uninterrupted.

Section transitions should be smooth.

Avoid scroll-jacking.

Avoid excessive parallax.

⸻

Signature Animation

The approved “Unified Workspace Reveal” is the landing page’s signature interaction.

Guidelines:

* Trigger only once during downward scrolling.
* Complete within a short, uninterrupted sequence.
* Preserve user control at all times.
* Respect reduced-motion preferences by replacing movement with a simple fade transition.

No other interaction on the page should compete with this moment.

⸻

Hover States

Hover should indicate interactivity.

Examples:

Small elevation.

Subtle background shift.

Border emphasis.

Icon color change.

Avoid dramatic movement.

⸻

Focus States

Every interactive element must have a clearly visible keyboard focus indicator.

Focus visibility should remain consistent across all components.

⸻

Loading States

Use skeleton placeholders for product previews or deferred content.

Avoid spinners where a skeleton better communicates layout.

⸻

Accessibility Standards

Accessibility is a quality requirement.

Not an enhancement.

⸻

Contrast

Maintain sufficient contrast for text, controls, icons, and interactive states.

Never sacrifice readability for aesthetics.

⸻

Keyboard Navigation

Every interactive component must be fully operable without a mouse.

Navigation order should follow the visual reading flow.

⸻

Focus Visibility

Do not remove focus indicators.

Ensure they are easy to distinguish from hover states.

⸻

Touch Targets

Interactive controls should provide comfortable touch areas on handheld devices.

Spacing should prevent accidental activation of neighboring controls.

⸻

Typography Accessibility

Avoid extremely light font weights for body copy.

Maintain comfortable line spacing.

Support browser zoom without layout breakage.

⸻

Motion Accessibility

Respect user preferences for reduced motion.

Replace large animated transitions with subtle opacity changes where appropriate.

⸻

Screen Readers

Provide meaningful labels for:

Navigation

Buttons

Icons

Interactive demos

Product previews

Charts should include textual summaries.

⸻

Responsive Rules

Responsive design should prioritize usability over preserving desktop composition.

⸻

Mobile

Single-column layouts.

Stack related content.

Reduce decorative elements before reducing readability.

CTAs remain easy to reach.

Navigation becomes a full-screen overlay.

⸻

Tablet

Preserve desktop hierarchy while simplifying grids.

Large visuals may stack beneath content.

Maintain generous spacing.

⸻

Desktop

Use two-column layouts where appropriate.

Maintain readable line lengths.

Avoid excessive horizontal stretching.

⸻

Section Rhythm

Alternate between:

Text-first

Product-first

Editorial

Interactive

Analytical

This variation creates a steady reading pace and prevents repetitive layouts.

⸻

Performance Guidance

Perceived performance contributes directly to product quality.

Recommendations:

* Prioritize rendering of the hero content.
* Defer non-essential decorative media.
* Optimize product imagery for responsive delivery.
* Keep animations lightweight and hardware-accelerated where possible.
* Ensure interactions remain responsive even on mid-range devices.

Visual polish should never come at the expense of responsiveness.

⸻

Frontend Implementation Guidance

The implementation team should view these guidelines as a system rather than isolated rules.

Preserve the Design System

Do not introduce new spacing values, radii, typography sizes, or motion styles unless a genuine design requirement exists.

Consistency is more valuable than local optimization.

⸻

Build Reusable Components

Navigation, buttons, cards, feature groups, testimonial cards, FAQ items, and principle cards should share common foundations.

Avoid page-specific variants that duplicate existing patterns.

⸻

Maintain Narrative Hierarchy

The landing page is designed as a story.

Avoid reordering sections or changing emphasis without validating the impact on user understanding.

⸻

Keep Product Imagery Authentic

Use real interface designs and representative content wherever possible.

Marketing mockups should closely reflect the production experience to build trust.

⸻

Prioritize Accessibility and Performance

Every visual enhancement should be evaluated against accessibility, responsiveness, and perceived performance.

If an effect reduces clarity or usability, prefer the simpler implementation.

⸻

Quality Checklist

Before implementation is considered complete, verify that:

* All sections follow the approved spacing system.
* Typography hierarchy is consistent throughout.
* Containers maintain readable widths across breakpoints.
* Navigation behaves predictably on all devices.
* Components use consistent radius, borders, and elevation.
* Motion is subtle, purposeful, and respects reduced-motion preferences.
* Keyboard navigation and focus states are fully supported.
* Product imagery accurately reflects the application.
* Responsive layouts preserve hierarchy without introducing clutter.
* Performance remains smooth across supported devices.

⸻

Guiding Principle

The landing page should feel like an extension of the Synaptic product itself.

Every design decision should reinforce the same qualities users will expect after signing in:

* Calm
* Intelligent
* Reliable
* Focused
* Premium
* Purposeful

If an implementation choice makes the interface appear louder, more complex, or less trustworthy than intended, it should be reconsidered in favor of the simpler, more cohesive solution.

## Design Tokens

All visual decisions should be implemented through reusable design tokens rather than hardcoded values.

Tokens should include:

- Colors
- Typography
- Font sizes
- Font weights
- Spacing
- Border radius
- Shadows
- Z-index
- Animation durations
- Transition curves

Frontend components must consume these tokens instead of defining local values.

This ensures consistency, simplifies theme updates, and enables scalable maintenance across the platform.

## Icon Usage Principles

Icons should support comprehension, not decoration.

Guidelines:

- Pair icons with labels in primary navigation.
- Avoid icon-only actions unless universally recognized.
- Maintain consistent stroke weight.
- Do not mix multiple icon libraries.
- Reserve filled icons for active states where appropriate.
- Keep icon alignment consistent within buttons, cards, and lists.

## Empty State Philosophy

Empty states should educate rather than disappoint.

Each empty state should include:

- A clear title
- A concise explanation
- A primary next action
- Optional illustration where appropriate

Avoid messages that simply state "No data."

Guide users toward meaningful progress.

## Microcopy Guidelines

Interface text should reduce cognitive load.

Buttons, labels, placeholders, helper text, and validation messages should:

- Be concise.
- Use plain language.
- Avoid unnecessary technical jargon.
- Prefer action-oriented wording.
- Never blame the user.

Examples:

✓ Create Workspace

✓ Join Community

✓ Continue

instead of

✗ Submit

✗ Execute

✗ Confirm
